# Research log

- ROM is 1 MiB, 64 × 16 KiB, MBC5, CGB-compatible; split into 64 bank files.
- `mgbdis` v3.0 generated per-bank assembly.
- Startup path is `$0100` -> `$0150`.
- Graphics regions `$5E9F/$605F/$607F/$61BF/$627F` were extracted and visually inspected.
- `$607F` is a sliding 32-byte window advancing by two bytes; previous non-overlapping-pair preview logic is incorrect.
- `$C2FE-$C307` is initialized from identity values and transformed into two five-byte sequences using flags `$C308/$C309`; semantic meanings remain unknown.
- `$42B6` points to ten embedded records; record processing copies 16-byte blocks. Record semantics remain unknown.
- `$C4E9` data is transferred as 80 byte pairs, with `$5A` added to second bytes and `$40` row stepping. Do not label it a standard tilemap without evidence.
- Bank 3B `$7161` creates `$FF`-padded blocks with complemented duplicated source bytes.
- Bank 3C `$6598` creates zero-padded blocks with unchanged duplicated source bytes.
- Both use `$C42B` as a loop-count input and switch to bank `$36`; exact semantic purpose unknown.
- `$C42B` reads are known, but its definitive writer/initialization path is not established.
- Suspicious byte soup around bank 36 `$6700` should not be treated as code; bank 33 also begins with likely data.
- Bank 0 `$0020` contains raw bytes `C3 7A 00` and jumps to `$007A`; `$007A` uses `B` as the MBC5 low-bank value, saves/restores the `$FFE0` current-bank shadow, and restores `AF` around the `$124C` call. `$124C` returns `DE` as the output end and `HL` as the decoded byte count; the stream cursor is not returned.
- `$124C` was traced as a variable-output back-reference decompressor: a two-byte header gives the number of eight-token control groups (plus one) and the length/distance token split; control bits are read MSB-first, selecting literals or backward matches. It has no fixed output-size argument or destination-capacity check and has no explicit `$7FFF` bank-boundary handling.
- Example caller evidence: bank `$3D:$4036` selects bank `$33`, passes stream `$7810` to RST `$20`, and copies 2,048 output bytes to `$8800`; the stream decodes to 2,048 bytes. The stream at bank `$33:$7164` decodes to 2,052 bytes while its caller copies 2,048. Direct `$124C` streams at bank `$29:$5B04`, `$29:$5738`, and bank `$2C:$42CA` decode to 326, 1,042, and 692 bytes respectively; their callers copy 320, 1,040, and 608 bytes. All stream offsets and counts were checked against raw ROM bytes with a read-only Python decoder.
- `$C42B` is read by bank `$36:$4000` (file `$D8000`) through the descriptor pointer at `$C312` (normally `$C429`): the byte at descriptor offset 2 is loaded as an entry count, with payload at `$C42C`. Builders write it indirectly via `[HL+]`, not with an absolute `$C42B` store.
- Bank `$3B:$6EDD` (file `$EEDDD`) points the descriptor at `$C529` and calls `$7161` at `$6EE9`; `$7161` (file `$EF161`) writes count `$0F` and 15 payload bytes before invoking bank `$36:$4000`. Bank `$3C:$5FAC` (file `$F1FAC`) similarly calls `$6598` at `$5FB8`; `$6598` (file `$F2598`) writes count `$09` and nine payload bytes before invoking the same bank `$36` processor. Each then generates `2*$C42B` 32-byte blocks at `$C929`; their callers copy only half that generated output (16 bytes per loop iteration). The bank `$3C` builders at `$6358`, `$64E7`, `$74BB`, and `$74C1` additionally write counts `$12`, `$03`, `$12`, and `$0F`, respectively, plus matching payload lengths.
- `$C42B` is a shared byte within the `$C429` work/descriptor region: bank `$3D:$4705` and bank `$3E` RST `$20` paths decompress into `$C429`, so those paths overlap the byte. Their precise output extents and whether downstream code interprets the overwritten byte as a count are still unknown. No direct absolute store to `$C42B` was found; do not treat it as a stable global variable.
