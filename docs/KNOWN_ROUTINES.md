# Known routines

Confidence: **confirmed** = directly traced; **strongly indicated** = multiple observations but semantics unclear; **hypothesis** = needs proof.

## Bank 0
- `$0000` RST 00 dispatcher: bytes `78 E0 E0 EA 00 20 E9`; custom indirect/banked dispatch sequence. Full calling convention still to document.
- `$0020` RST 20 vector: raw bytes `C3 7A 00`, jumping to `$007A` (bank 0, CPU/file offset `$0020`).
- `$007A` RST 20 wrapper (bank 0, CPU/file offset `$007A`; **confirmed**): input `B` is the source ROM bank, `HL` points to a compressed stream in that bank's `$4000-$7FFF` window, and `DE` is the output start. It saves `AF`, saves the current-bank shadow at `$FFE0` on the stack, writes `B` to `$FFE0` and MBC5 register `$2000`, calls `$124C`, then restores the shadow and `$2000`. It restores `AF`; the decoder returns the output end in `DE` and output byte count in `HL`. `BC` is clobbered. The wrapper writes only `$2000` (the MBC5 low bank register); this ROM has 64 banks, so no high bank bit is needed.
- `$124C` compressed-stream decoder (bank 0, CPU/file offset `$124C`; **confirmed**): input `HL` points to a stream and `DE` to the output start. The first two bytes encode `(control_group_count - 1)` in the low 14 bits and a token-field split in the top two bits of byte 2. The decoder processes that many groups plus one; each group is one control byte followed by eight MSB-first tokens. A clear control bit copies one literal byte. A set bit reads one token whose low `4 - top_two_bits` bits encode match length minus one, and whose remaining high bits encode backward distance minus one. Thus this is a back-reference decompressor, not a byte-for-byte copy. The output byte count is data-dependent and is not specified as a fixed byte count in the header. The routine has no output-capacity argument or bounds check. On return, `DE` is the output end and `HL` is the number of decoded bytes; the compressed-stream cursor is not returned, and `BC` is clobbered.
- `$0DD4` / `ProcessBankedRecord` (bank 0, file offset `$000DD4`, length `$1B0`; **confirmed behavior, semantic type unknown**): input `HL` points to a state record. The routine clears bit 3 of its first byte, tests flag bits 0 and 4, and uses the byte at offset `$1C` as a countdown on one branch. It selects the MBC5 low bank from record offset `$11`, reads a little-endian pointer at `$12-$13`, advances the byte at `$14` by 4, and examines data relative to that pointer/offset. It may update a related record pointer and flags; raw field meanings are not established. A related entry at `$0E28` shares much of the control flow and the `$0F7D` bank-restore exit. `$0DD4` saves the current-bank shadow from `$FFE0` and restores both `$FFE0` and `$2000` before returning at `$0F83`. Bank 4 calls it at `$5E16`, `$5E1C`, `$5E8F`, `$5E95`, and `$5E9B`; other direct callers are bank 3B `$4233/$5029/$502F/$5035/$50A9/$50AF/$50B5`, bank 3C `$41E4/$41EA/$41F0/$41F6/$56E0`, bank 29 `$4EEF`, bank 2A `$49A7`, bank 3E `$5252/$627E/$6B09`, and bank 3F `$4198/$41B2/$41C5/$4628/$4B16`. These 27 call sites were checked in the reference disassembly and staged bank-4 source; they load record addresses into `HL`.
- `$0F84` / `CopyThreeBytesFromHLToDE` (bank 0, file offset `$000F84`, length 10; **confirmed**): copies three consecutive bytes from `[HL]` to `[DE]`, advancing both pointers by 3. Called from `$0DD4` at `$0EC5` and `$0EE8`.
- `$10C0` / `CopyCgbTilemapRows` (bank 0, file offset `$0010C0`, length 42; **confirmed**): inputs `HL` = VRAM base, `DE` = interleaved source, `B` = bytes per row, and `C` = row count. For each cell it writes the first source byte to VRAM bank 1 (CGB tile attributes), the second to VRAM bank 0 (tile ID), then advances the destination by `$20` for each row. Each write waits until the PPU is in a writable STAT mode.
- `$10EA` / `FillCgbTilemapRows` (bank 0, file offset `$0010EA`, length 39; **confirmed**): inputs `HL` = map start, `D` = repeated tile ID, `E` = repeated CGB attribute, `B` = cells per row, `C` = row count. Writes each value into its respective VRAM bank, advancing by one tile per cell and `$20` bytes per row. Each write waits until STAT mode 0.
- `$1111` / `FillCgbTilemapRowsWithIncrementingTileIds` (bank 0, file offset `$001111`, length 40; **confirmed**): same row layout and bank selection as `$10EA`, but increments tile ID `D` after each cell; the attribute byte `E` stays constant.
- `$1139` / `FillCgbTilemapColumnsWithIncrementingTileIds` (bank 0, file offset `$001139`, length 42; **confirmed**): inputs `HL` = map start, `D` = initial tile ID, `E` = attribute, `B` = column count, `C` = rows per column. Writes one column at a time, stepping `$20` between rows and incrementing the tile ID for each next column.
- `$1163` / `FillStatSafeMemoryWithWord` (bank 0, file offset `$001163`, length 31; **confirmed**): inputs `HL` = repeated 16-bit value, `DE` = destination, and `B` = number of 16-byte blocks. Writes alternating `H,L` bytes for 16 bytes per block, polling STAT mode before each write. Callers use it to initialize 32 bytes of VRAM tile data.
- `$1188` / `Copy16BytesPerBIteration` (bank 0, file offset `$001188`, length 52; **confirmed**): input `HL` = source, `DE` = destination, `B` = block count. Copies exactly 16 bytes per iteration and advances both pointers by 16. Used by the bank `$3F` startup path after decompression and by banks `$3D/$3E` graphics loaders.
- `$11C2` / `Copy16BytesPerBIterationWithStatWait` (bank 0, file offset `$0011C2`, length 22; **confirmed**): inputs `HL` = source, `DE` = destination, `B` = 16-byte block count. Copies 16 bytes per iteration, waiting for STAT mode 0 before each byte. Callers in banks `$3A` and `$3C` use it to copy tile data to VRAM.
- `$007A`/`$124C` source-boundary caveat (**confirmed from control flow**): `$124C` advances `HL` while reading but contains no bank-boundary check or bank switch. Callers must provide a stream wholly readable in the currently selected mapping; crossing `$7FFF` is not handled by this helper.
- `$007A` caller evidence: bank `$3D`, CPU `$4036-$4047` (file offset `$F4036`), selects bank `$33`, decompresses stream `$7810` (bank `$33`, file offset `$CF810`) to `$C329`, then copies `B=$80` blocks of 16 bytes (2,048 bytes) to `$8800`. The stream decodes to exactly 2,048 bytes. A second stream at bank `$33:$7164` decodes to 2,052 bytes, while its caller copies 2,048 bytes to `$9000`.
- Direct `$124C` caller evidence: 31 call sites occur in banks 0, 4, 5, `$2A`, `$29`, and `$2C`. Examples: bank `$29:$5B04` (file `$A5B04`) decodes to 326 bytes; its caller copies 320. Bank `$29:$5738` (file `$A5738`) decodes to 1,042 bytes; its caller copies 1,040. Bank `$2C:$42CA` (file `$B02CA`) decodes to 692 bytes; its caller copies 608. These demonstrate that decoded output can exceed the subsequent copy length.
- `$0150` startup: initializes stack, cartridge RAM, RAM ranges and LCD registers; calls `$137C`, selects bank `$2C`, calls `$0308`.
- `$137C`: checks `$C000`, selects bank `$2E` or `$2F`, calls `$460E`.
- `$23A8` / `CopyTilesToVram` (bank 0, file offset `$0023A8`; **confirmed**): input `A` is the tile count, `HL` source, `DE` VRAM destination. Callers use even tile counts. It halves `A` and copies 32 bytes per outer iteration (four bytes per pass, eight passes), for `16*A` bytes; `HL` and `DE` advance by the copied length. Before each of the four byte writes in each pass it waits for `rSTAT` bit 1 to clear. After each 32-byte group it calls `$248D` and `$0417`. All five direct calls are in bank 4: `$5C4A`, `$5C5E`, `$5C69`, `$5C7F`, and `$5E4F`.
- `$0F8E` / `Copy32BytesAndClear29` (bank 0, file offset `$000F8E`, length 16; **confirmed**): input `DE` points to a 32-byte source and `HL` to the destination. Copies 32 bytes, then clears the following 29 destination bytes. Returns with `DE` advanced 32 and `HL` advanced 61; `B` is clobbered and `A` is zero. Bank 4 calls it nine times using template `$651F`: six calls in `SetupBank4GraphicsState` initialize blocks at `$D700`, `$D740`, `$D780`, `$D7C0`, `$D800`, and `$D840`; three calls in `$5E42` initialize `$D700`, `$D740`, and `$D780` again. The initialized block fields are not semantically identified.

## Bank 4
- `$5C42` / `SetupBank4GraphicsState` (bank 4, file offset `$011C42`; **confirmed entry**): bank 0 `$1E37-$1E58` selects bank `$2C` and dispatches `$40FE`, then sets `B=$04`, `HL=$5C42` at `$1E43-$1E48` and invokes RST `$08`. RST `$08` reaches the banked-call wrapper at `$0066`, which switches to bank 4, calls the target and restores the previous bank. This entry returns at `$5E10`. The initial graphics transfers call `CopyTilesToVram`: 28 tiles `$5E9F` to VRAM `$8800`; if `($C2C6 & $F0)==$20`, 22 tiles `$605F` to `$8AA0` and 12 tiles `$61BF` to `$8C00`; then 2 tiles from `$607F + ((2*SWAP_NIBBLES($C2D2)) & $FF)` to `$89A0`. The valid `$C2D2` selector domain is not established, so do not infer all possible source offsets. The rest of the routine configures additional graphics/state data; individual fields remain unlabeled.
- `$5E47-$5E4F`: loads 42 tiles from `$627F` to VRAM `$8800` via `CopyTilesToVram` (call at `$5E4F`).
- `$5E11` / `ServiceD700D740ForBIterations` (bank 4, file offset `$011E11`, length 27; **confirmed behavior**): input `B` is the iteration count. Preserves `HL`; each iteration calls bank-0 `$0DD4` with `HL=$D700` and then `$D740`, followed by `$248D` and `$0417`. `BC` is preserved around each iteration except that `B` decrements as the loop count. The meaning of the `$D700/$D740` blocks and updater `$0DD4` is unknown.
- `$5E42` / `Load42TilesAndInitializeD7Blocks` (bank 4, file offset `$011E42`, ends at `$5E8B`; **strongly indicated entry**): loads 42 tiles from `$627F` to VRAM `$8800`, initializes the `$D700/$D740/$D780` blocks from template `$651F`, applies literal patches, and conditionally adjusts bytes at offsets 6 in the first two blocks and offset 6 in the third when `($C2C6 & $F0)==$20`. Its caller has not been found; the exact meanings of the patched bytes and blocks remain unknown.
- `$5E8C` / `ServiceD700D740D780Once` (bank 4, file offset `$011E8C`, length 19; **confirmed behavior**): calls bank-0 `$0DD4` once each with `HL=$D700`, `$D740`, and `$D780`. The records' semantic types and updater effects remain unknown.

## Bank 2C
- `$401B` loads data at `$42CA` into `$C329` using `$124C`.
- `$42B6` contains ten little-endian pointers: `$4A5E,$4A88,$4A6B,$4A95,$4A76,$4AA2,$4A7F,$4AAF,$4ABA,$4AC7`. Callers use A as a byte offset (expected even values).
- `$421C/$4253/$4277`: read records, derive a count/offset from the first record byte, and copy 16-byte blocks from `$C329`. Semantic meaning unknown. `$429E/$42AA` contain tilemap-like sequences, but do not assume a standard tilemap.

## Bank 29
- `$4000`: copies ten bytes from `$572E` into `$C2FE-$C307`; first ten are identity values 0-9.
- `$49D7`: transforms those ten bytes into two five-byte sequences according to `$C308/$C309`; exact semantics unknown.
- `$53F4`: indexes `$C2FE`, takes low nibble, doubles it, stores to `$D92E` or `$DA2E`; saves raw field byte in `$C308/$C309`.
- `$4A2D` invokes bank 0 `$1028` with DE `$6B32`, HL `$C4E9`, B `$14`, C `$04`, A `$5A`. Helper copies 20 byte pairs per row, adds `$5A` to each second byte and advances destination by `$40`. Do not assume conventional 20x4 tilemap.

## Bank 3B
- `$6EDD` (file offset `$EEDDD`) sets the descriptor pointer at `$C429/$C42A` to `$C529`, positions `HL` at `$C42B`, then calls `$7161`.
- `$7161` (file offset `$EF161`; its only direct caller is bank `$3B:$6EE9`) writes `$0F` at `$C42B`, then copies 15 bytes from caller `DE` into `$C42C-$C43A`. It invokes bank `$36:$4000` through RST `$08`, then uses `2*$C42B` as its output-loop count. Each loop creates a 32-byte block at `$C929`: four `$FF`, 12 complemented source bytes duplicated, then four `$FF`.
- `$6EF0` copies `32*$C42B` bytes from `$C929` using `$1188` (16 bytes per B iteration).
- `$6F8E` uses RST `$20` with HL `$462C`, B `$33`, DE `$C429`, then copies indexed 16-byte blocks to VRAM `$8AC0/$8BC0/$8CC0/$8DC0`.

## Bank 3C
- `$5FAC` (file offset `$F1FAC`) sets the descriptor pointer at `$C429/$C42A` to `$C529`, positions `HL` at `$C42B`, and calls `$6598`.
- `$6598` (file offset `$F2598`; its only direct caller is bank `$3C:$5FB8`) writes `$09` at `$C42B`, then copies nine bytes from caller `DE` into `$C42C-$C434`. It invokes bank `$36:$4000` through RST `$08`, then uses `2*$C42B` as its output-loop count. Each loop creates a 32-byte block at `$C929`: four zero bytes, 12 unchanged source bytes duplicated, then four zero bytes.
- A caller copies only `32*$C42B` bytes from this generated buffer, although the routine generates `64*$C42B`; do not claim all generated bytes are consumed by that caller.

## Shared `$C42B` descriptor/count byte
- Bank `$36:$4000` (file offset `$D8000`) follows the pointer stored at `$C312` (set to `$C429` by these builders), reads the descriptor pointer from `$C429/$C42A`, then reads the byte at `$C42B` as an entry count before processing the payload beginning at `$C42C`.
- Additional bank `$3C` builders write the byte indirectly via `[HL+]`: `$6358` writes `$12` followed by 18 bytes; `$64E7` writes `$03` and its three-byte payload; `$74BB` writes `$12` followed by 18 bytes; `$74C1` writes `$0F` followed by 15 bytes. The latter two are called in loops at `$721F` (file `$F321F`) and `$704C` (file `$F304C`).
- No absolute `ld [$C42B],a` store was found. `$C42B` is a field in the `$C429` descriptor/work area, not established as a persistent global count. Bank `$3D:$4705` and several bank `$3E` RST `$20` paths also decompress to `$C429`, overlapping `$C42B`; their exact decoded extents and resulting field values are not yet established.

## Banks 3D/3E
Similar routines use pointer tables `$4D78` (bank 3D) and `$4C3D` (bank 3E), invoke RST `$20` with B `$33`, DE `$C429`, then copy 0x400 bytes from `$C429` to VRAM `$8400` (64 × 16 bytes). They then load another bank 33 block from `$462C` and copy an indexed 16-byte block to `$9700`. Exact transfer/encoding depends on `$007A/$124C`.

## Bank 3F
- Startup at `$402E-$406C` calls RST `$20` three times with B=`$31`, decoding streams from bank `$31:$675D`, `$6CBD`, and `$7027` to `$C359`. The first stream decodes to 1,795 bytes; the following `Copy16BytesPerBIteration` call transfers only `$6E * 16 = 1,760` bytes to VRAM `$9100`. The second decodes to 1,441 bytes and transfers only `$5A * 16 = 1,440` bytes to VRAM `$8000`. These first two outputs are tile-aligned in the copied prefixes and are rendered in `analysis/graphics/previews/`; the untransferred tails are not included in the previews.
- The `$7027` stream decodes to 721 bytes. Its caller then invokes `$10C0` with `HL=$9C00`, `B=$14`, `C=$12`, and `DE=$C359`; the routine transfers 20-by-18 interleaved attribute/tile pairs to CGB VRAM banks 1 and 0, consuming 720 bytes. One decoded trailing byte is not used by that call.
- The three decoded source spans consume 1,379, 875, and 290 compressed bytes respectively. Their source spans overlap at the next stream start by 3 bytes and 1 byte; keep that overlap explicit rather than treating the streams as disjoint ROM regions. The decoder output lengths and copied prefixes were cross-checked against the local `$124C` implementation and raw ROM bytes.
